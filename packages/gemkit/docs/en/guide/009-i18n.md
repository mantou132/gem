# Internationalization

Put language packs in `src/locales` and Gemkit generates the i18n instance, language-prefixed URLs and
the server-side language detection.

```
src/locales/
  en.json    default language, /about
  zh.json    /zh/about
```

A JSON file is a language, the file name is the language code. The default language has no path prefix
by default, other languages use `/<lang>`.

## Configuration

```ts
pluginGemkit({
  defaultLanguage: 'en',
  prefixDefaultLanguage: false,
});
```

| Option                  | Description                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `defaultLanguage`       | The default language. Defaults to `en` when present, otherwise the first language by file name.              |
| `prefixDefaultLanguage` | Put the default language under a prefix too (`/en/about`). Unprefixed paths redirect to the user's language. |

The default language must have a language file, otherwise the build fails.

Every page exists in every language. There are no duplicated page files in `src/pages`: `/zh/about`
renders the same `src/pages/about.ts` module with the `zh` language pack.

## Generated module

`$gemkit/i18n` exports:

| Export                  | Description                                                   |
| ----------------------- | ------------------------------------------------------------- |
| `i18n`                  | The `I18n` instance, typed with the default language pack.    |
| `languages`             | The language codes, sorted by file name.                      |
| `defaultLanguage`       | The default language code.                                    |
| `prefixDefaultLanguage` | Whether the default language has a prefix.                    |
| `localizePath`          | `(lang, path?) => string`, the path with the language prefix. |

```ts
import { languages, localizePath } from '$gemkit/i18n';

html`<p>${i18n.get('title')}</p>`;

// Switch language with a normal link, the page reloads.
html`${languages.map((lang) => html`<a href=${localizePath(lang)}>${lang}</a>`)}`;
```

`i18n` is a Gem `I18n` instance. See the [Gem i18n documentation](https://gemjs.org/en/guide/advance/i18n)
for variable substitution, fallback languages and cache.

## Page content

Pages, layouts and elements read translations from `i18n.get`. Since the language pack is loaded before
rendering, the first server render and hydration use the same language:

```ts
@page({ title: () => i18n.get('about') })
export default class AboutPage extends GemElement {
  @template()
  #content = () => html`<h1>${i18n.get('about')}</h1>`;
}
```

The language is selected from the URL, not from `navigator.language`. A request without a prefix uses
the default language; a request with an unknown prefix is a normal 404 (or the path is treated as part
of the default language path).

## Unprefixed paths

When `prefixDefaultLanguage` is enabled, an unprefixed path (for example `/` or an old link) belongs to no
language and redirects to the first match of:
1. The language the user used last, stored in the `gemkit-lang` cookie when a prefixed page is visited
2. The language preferred by the browser, read from `Accept-Language` on the server; `zh-CN` matches
   `zh-CN`, then `zh`
3. The default language

When prerendering, Gemkit writes redirect pages for unprefixed paths. A script in the page picks the
language from `document.cookie` and `navigator.languages` with the same rules, and only redirects to
languages the page exists in, so static hosting needs no server.

## Switching language

Use a normal `<a href>` with `localizePath`. Switching language reloads the page: the base path, the
language pack and all content change, so a full reload is the simplest and most consistent behavior.
It also matches the server-rendered result.

```ts
html`<a href=${localizePath('zh')}>中文</a>`;
```

## Dynamic paths

[`paths`](./002-pages.md#dynamic-paths) is called for each language, so a route can have different pages
in different languages:

```ts
export function paths({ lang }: { lang: string }) {
  return posts[lang].map(({ slug }) => ({ slug }));
}
```


## Template

The `<html lang>` attribute is set by the server to the current language. Add the language to
`src/index.html` only if you want a default for non-rendered documents; Gemkit replaces it on rendered
pages.

## API routes

API routes are not localized. They always use their path without a language prefix, for example
`/api/likes/1`, regardless of the current language.
