# API

Everything in this page is imported from `@mantou/gemkit`, unless stated otherwise. All of them are auto-imported,
except `HttpError`, `formatTitle` and types.

## Routes

### page

```ts
page(options?: string | PageOptions<P, D>): ClassDecorator
```

Marks the default export of a page module. A string is the page title, the same as `{ title: options }`.

```ts
@page<{ slug: string }, Post>({ load: ({ params }) => getPost(params.slug) })
export default class PostPage extends GemElement {
  @property params!: { slug: string };
  @property data?: Post;
}
```

### layout

```ts
layout(options?: LayoutOptions<P, D>): ClassDecorator
```

Marks the default export of `_layout.ts`. A layout applies to the pages below it and is kept while
navigating between them.

### PageOptions

| Option  | Type                                                               | Description                               |
| ------- | ------------------------------------------------------------------ | ----------------------------------------- |
| `title` | `string \| (ctx: RouteContext<P, D>) => string \| Promise<string>` | The page title.                           |
| `load`  | `(ctx: LoadContext<P>) => D \| Promise<D>`                         | Isomorphic data loading before rendering. |
| `meta`  | `Meta \| (ctx: RouteContext<P, D>) => Meta \| Promise<Meta>`       | `<meta>` tags of the page.                |
| `paths` | `(ctx: { lang: string }) => P[] \| Promise<P[]>`                   | Params of the dynamic route to prerender. |

`LayoutOptions` has `load` and `meta`.

### RouteContext

```ts
interface RouteContext<P extends Params = Params, D = unknown> {
  params: P;
  data: D;
}
```

`params` are the matched route parameters. `data` is the result of `load`; for `load` itself, it is the
result of the sibling server module `load`.

### Meta

```ts
type Meta = Record<string, string | undefined>;
```

Keys containing `:` become `<meta property>`, others `<meta name>`. `undefined` values are skipped.

## Server modules

A sibling `<page or layout>.server.ts` exports these values. They only run on the server.

### load

```ts
export function load(ctx: ServerLoadContext<P>): unknown | Promise<unknown>;
```

Returns JSON-serializable data. It is passed to the page or layout `load` as `data`, or used directly when
there is no `load` option. It can [`redirect`](#redirect), [`error`](#error) or [`notFound`](#notfound).

### paths

```ts
export function paths(ctx: { lang: string }): Params[] | Promise<Params[]>;
```

The params of the dynamic route to prerender. It is called once per language and takes precedence over
the page `paths` option. Only pages use it.

### prerender

```ts
export const prerender = false;
```

Disables prerendering for the route. In a layout it applies to all pages below it.

### actions

```ts
export const actions: Record<
  string,
  (ctx: ServerLoadContext) => unknown | Promise<unknown>
>;
```

Handlers for `POST <page path>?/<name>`. The form `action="?/login"` calls `actions.login`. A submit
button with `formaction="?/logout"` calls `actions.logout` from the same form. Return a
JSON-serializable value for [`submitAction`](#submitaction), or use `redirect`, `error` and `notFound`.

### revalidate

```ts
export const revalidate = 60;
```

Seconds for incremental static regeneration (ISR). `gemkit start` prerenders and caches the page on the first
request; once stale, it responds with the old content and rerenders in the background. When a layout and a
page both set it, the smallest value is used. See [Deploy](../guide/011-deploy.md#incremental-static-regeneration).

## API routes

A `*.server.ts` without a page module exports `GET`, `POST`, `PUT`, `PATCH` and `DELETE` handlers, see
[API routes](../guide/006-api-routes.md).

### endpoint

```ts
endpoint(schema: StandardSchemaV1, handler: (ctx: ServerLoadContext<P>, input: Output) => R): RequestHandler;
```

Validates and transforms the input with a [Standard Schema](https://standardschema.dev). When validation fails
it responds `400`, and the `issues` of the error are the validation issues. The input type of `$gemkit/api` is
the output type of the schema.

### revalidatePath

```ts
revalidatePath(pathname: string): Promise<void>;
```

Clears the ISR cache of a page on the server, so the next request rerenders it. `pathname` includes the
language prefix. There is no cache in development or on a static host.

## Request

### ServerLoadContext

```ts
interface ServerLoadContext<P extends Params = Params> extends RequestEvent {
  params: P;
}
```

### RequestEvent

| Field     | Type      | Description                                                      |
| --------- | --------- | ---------------------------------------------------------------- |
| `url`     | `URL`     | The page URL, including the language prefix.                     |
| `path`    | `string`  | The page path without the language prefix, as matched by routes. |
| `request` | `Request` | The current request. Not available when prerendering.            |
| `cookies` | `Cookies` | Request cookies. Not available when prerendering.                |
| `locals`  | `Locals`  | Per-request data shared by server code.                          |

### getRequestEvent

```ts
getRequestEvent(): RequestEvent;
```

Returns the request event of the current server request. It throws outside a request, for example during
module evaluation or after the response has finished. It is scoped per request, so the result must not be
stored in a module-level variable.

### redirect

```ts
redirect(status: 301 | 302 | 303 | 307 | 308, location: string): never;
```

Throws a redirect. `location` includes the language prefix. It works in `handle`, `load`, `actions` and API
routes.

### error

```ts
error(status: number, message?: string): never;
```

Throws an error that renders the error page with the given status.

### notFound

```ts
notFound(): never;
```

Same as `error(404, 'Not Found')`.

### HttpError

```ts
class HttpError {
  status: number;
  message: string;
  issues?: SchemaIssue[];
}
```

The error thrown by `error()`, and by `$gemkit/api` when the response is not OK. `issues` are the schema
validation issues.

### submitAction

```ts
submitAction(form: HTMLFormElement, submitter?: HTMLElement | null): Promise<unknown>;
```

Submits the form without a page reload. On success, reloads the current page data and returns the action
result. On redirect, navigates on the client. On error, renders the error page. The form has `aria-busy`
during the request. It throws when the request itself fails.

### invalidate

```ts
invalidate(): Promise<void>;
```

Reloads the data of the current page and layouts without reloading the page; the page element is reused, for
example after a mutation through an API route. Prefetched results and the history cache are not used anymore.
It resolves when the data is loaded.

### Cookies

```ts
interface Cookies {
  get(name: string): string | undefined;
  set(name: string, value: string, options?: CookieOptions): void;
  delete(name: string, options?: Pick<CookieOptions, 'path' | 'domain'>): void;
}
```

`set` and `delete` add a `Set-Cookie` header to the response. A later `get` in the same request sees the
new value.

### CookieOptions

| Option     | Type                          | Default         |
| ---------- | ----------------------------- | --------------- |
| `path`     | `string`                      | `'/'`           |
| `domain`   | `string`                      |                 |
| `maxAge`   | `number`, seconds             |                 |
| `expires`  | `Date`                        |                 |
| `httpOnly` | `boolean`                     | `true`          |
| `secure`   | `boolean`                     | `true` on HTTPS |
| `sameSite` | `'Strict' \| 'Lax' \| 'None'` | `'Lax'`         |

### Locals

```ts
interface Locals {}
```

An empty interface extended by the app. Populate it in `handle` and read it from `load`, `actions`, API
routes and server elements.

```ts
declare module '@mantou/gemkit' {
  interface Locals {
    user?: User;
  }
}
```

## Server elements

### server

Marks a class as a server-only element, or a method or field to run during server rendering.

```ts
@server()
class ServerOnly extends GemElement {}
```

`@server()` on a member runs it during server rendering and serializes its state. The result must be
JSON-serializable.

### lazy

```ts
lazy(options?: { on?: 'interaction' | 'load' | 'visible' }): ClassDecorator
```

Keeps the server HTML until the client loads the element code and hydrates. `on` defaults to
`'interaction'`.

### client

```ts
client(): ClassDecorator
```

Renders the element only on the client. The server outputs the tag, and the client renders without
hydration. The module is replaced with an empty module in the server build.

## Utilities

### formatTitle

```ts
formatTitle(title: string | undefined, { title, titleTemplate }: TitleOptions): string;
```

Applies the site title and title template, the same way Gemkit does.

### TitleOptions

```ts
interface TitleOptions {
  title?: string;
  titleTemplate?: string;
}
```

## Generated modules

`i18n` from `$gemkit/i18n` and `apis` from `$gemkit/api` are auto-imported.

### $gemkit/i18n

| Export                  | Type                                      |
| ----------------------- | ----------------------------------------- |
| `i18n`                  | `I18n<typeof defaultMessages>`            |
| `languages`             | `string[]`                                |
| `defaultLanguage`       | `string`                                  |
| `prefixDefaultLanguage` | `boolean`                                 |
| `localizePath`          | `(lang: string, path?: string) => string` |

Without a `locales` directory, `i18n` is `undefined`, `languages` is empty and `defaultLanguage` is
`''`. See [Internationalization](../guide/009-i18n.md).

### $gemkit/api

`apis` is generated from the API routes. Static segments are properties, dynamic segments are function
calls and HTTP methods are the final call. The input and result are inferred from the handler. A JSON
response is parsed; other responses return the `Response`. A non-OK response rejects with `HttpError`.
When the handler redirects, the client navigates and the call does not resolve.

```ts
const likes = await apis.api.likes(slug).GET({ page: 1 });
```

`GET` and `DELETE` send the input as the query, other methods send JSON.
